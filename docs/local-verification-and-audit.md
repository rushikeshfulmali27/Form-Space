## Audit scope and interpretation

The full registry response is saved in `npm-audit-report.json`. It reports **30 affected package entries: 1 critical, 21 high, 7 moderate, 1 low**. These include parent packages marked vulnerable because of a shared transitive dependency; they are not 30 independent remotely exploitable flaws.

Assessment used the installed dependency tree, application imports/routes, framework code, and linked advisories. No exploit was attempted against secret files. Application input is design text/JSON; the API does not accept image, font, archive, YAML, glob, or browser-query uploads. The editor is static HTML and JavaScript served by GET routes; the API is a POST route, not a React Server Function. Framework-level paths still need attention even when the application does not import a vulnerable helper directly. A package marked `devDependency` can also participate in this project's server bundle, so that label alone does not establish safety.

## Suggested implementation order

1. Patch Vite to 8.0.16 and validate the Windows dev server first.
2. Test the matching React 19.2.8 trio plus Next 16.3.8 as a small compatibility branch/change set. Alternatively, if choosing Vinext 1.2.1, use its required React 19.3.1 trio and RSC plugin >=0.5.37 instead; do not mix the two plans.
3. Upgrade Cloudflare tooling together, reviewing its Miniflare transition and the Sharp override. Verify no vulnerable duplicate remains.
4. Refresh compatible transitive build/lint packages selectively. Review unused database, resolver, and lint dependencies before removing them. Do not accept the audit's automatic major downgrades.
5. After each coherent change set: run `npm test`, TypeScript checking, the appropriate portable production build, both local routes, demo create/refine, and a fresh `npm audit --json`. Once API credits are available, repeat live create/refine, check preservation of manually edited fields, and check that failures preserve the last good design.

These are proposals, not applied fixes. Registry metadata and audit recommendations establish candidates, not verified application compatibility. No `npm audit fix` or `npm audit fix --force` was run.
